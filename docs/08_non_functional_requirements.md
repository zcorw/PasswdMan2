# 非功能要求

## 性能

- 登录接口 P95 响应时间小于 800ms，不含密码哈希成本的环境差异。
- 条目列表查询 P95 响应时间小于 300ms。
- 搜索结果在 500ms 内返回。
- 单用户 10,000 条密码记录下仍可正常分页检索。

## 可用性

- MVP 目标可用性 99.5%。
- 数据库故障应有明确错误提示和日志。
- PWA 离线状态应提示无法同步，并展示已缓存应用壳和离线页。
- 密码生成器可在离线状态下使用。

## 可维护性

- 认证、加密、个人保险库、条目、审计模块边界清晰。
- 关键安全函数必须有单元测试。
- API 错误格式统一。
- 非对称加密通讯逻辑应封装为独立客户端和服务端模块，避免散落在各业务接口中。

## 可扩展性

- 支持后续增加浏览器插件、原生移动 App、导入导出和高级安全能力。
- 数据模型保持简单，MVP 不预留团队共享表。
- 加密方案应支持版本号，便于未来迁移。
- PWA 缓存策略应可扩展到后续离线加密保险库，但 MVP 不实现完整离线保险库。

## 兼容性

- 支持最新版 Chrome、Edge、Firefox、Safari。
- 移动端支持 iOS Safari 和 Android Chrome 的最近两个主版本。
- UI 以移动端为主设计，必须优先验证 360x740、390x844、430x932 等手机视口。
- PWA 必须提供 `manifest.webmanifest`、应用图标、主题色、启动 URL 和 display mode。
- Service Worker 应兼容主流 Chromium 浏览器、Firefox 和 Safari 的可用能力差异。
- iOS PWA 能力有限时，应降级为响应式 Web 体验，不影响核心功能。

## PWA 要求

- 提供 Web App Manifest，包含 name、short_name、start_url、scope、display、theme_color、background_color、icons。
- 注册 Service Worker，并采用明确的静态资源缓存策略。
- 提供离线页和网络恢复后的重试机制。
- 支持添加到主屏幕或桌面安装。
- Lighthouse PWA 检查应通过基础可安装项。
- 不缓存敏感 API 明文响应。

## 国际化

- MVP 可先使用中文界面。
- 后续应支持中英文切换。
- 文案应集中管理，避免散落硬编码。

## 日志与监控

- 记录请求 ID、错误堆栈、接口耗时。
- 不记录敏感明文。
- 监控登录失败率、接口错误率、数据库连接数。

## 备份与恢复

- 数据库每日备份。
- 备份数据加密保存。
- 定期验证恢复流程。
- 待确认事项：备份保留周期和合规要求。

## 部署环境

- 用户明确提出：后端框架采用 Python + FastAPI。
- 用户明确提出：部署方式使用 Docker Compose。
- 用户明确提出：使用 Nginx 作为反向代理。
- 用户明确提出：数据库采用 PostgreSQL。
- 用户明确提出：ORM/迁移采用 SQLAlchemy + Alembic。
- 行业通用默认：生产环境必须启用 HTTPS。
- 用户明确提出：客户端与服务端通讯要用非对称加密方式通讯，部署时必须配置服务端公私钥、key_id、公钥轮换策略和密钥过期策略。
- 用户明确提出：项目以 PWA 形式开发，部署必须正确提供 Manifest、Service Worker、图标和 HTTPS。
- 密钥通过环境变量或密钥管理服务注入。
- Docker Compose 至少包含 frontend、backend、postgres、nginx 服务。
- Nginx 负责 HTTPS 终止、静态资源分发、PWA 文件响应头、API 反向代理。
