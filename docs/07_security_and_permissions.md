# 安全与权限

## 认证

- 登录密码必须使用强哈希算法保存，例如 Argon2id 或 bcrypt。
- 主密码用于派生加密密钥，不应直接保存明文。
- 会话使用 HttpOnly、Secure、SameSite Cookie 或等效安全机制。
- 连续登录失败需要限流和安全提示。
- 记住账号只允许在客户端本地保存邮箱或账号名，不得保存登录密码、主密码、会话令牌、恢复码、私钥或任何保险库密钥。
- 记住账号数据不应写入 Service Worker Cache；可使用 localStorage 或同等客户端存储，但必须有清除入口。

## 非对称加密通讯

- 客户端与服务端之间的敏感通讯必须使用非对称加密机制保护。
- 生产环境必须启用 HTTPS；HTTPS 是基础传输保护，不能替代应用层非对称加密通讯要求。
- 非对称通讯采用 X25519 + AES-GCM。
- 服务端提供可轮换的 X25519 公钥，客户端通过 X25519 密钥交换协商临时会话密钥，再使用 AES-GCM 加密业务载荷；密钥交换、key_id、nonce、timestamp、algorithm 必须随请求传递。
- 如响应包含敏感数据，服务端必须使用客户端临时公钥或协商出的会话密钥保护响应载荷。
- 服务端必须校验 nonce 与 timestamp，防止重放攻击。
- 公钥轮换时必须保留短期兼容窗口，并能拒绝过期 key_id。

## 授权

- MVP 只有普通用户个人资源权限。
- 所有 Vault、PasswordItem、Session、AuditLog、RecoveryCode 操作必须校验 user_id 归属。
- 服务端必须做权限校验，不能只依赖前端隐藏按钮。
- 不提供团队角色、管理员角色、跨用户共享权限。

## 敏感数据处理

- 主要密码、副密码、副密码备注、TOTP 密钥、备注、自定义敏感字段应加密存储。
- 第一版服务端只同步加密后的密码库和被主密码派生密钥加密的 Vault Key。
- 用户在任意设备输入主密码后，客户端本地派生密钥解开 Vault Key，再用 Vault Key 解密同步来的密码数据。
- 服务端不得保存或接触主密码、主密码派生密钥、Vault Key 明文、主要密码明文、副密码明文或副密码备注明文。
- 服务端日志不得记录密码、密钥、主密码、明文恢复码。
- 复制和显示主要密码或副密码的操作必须记录审计日志。
- 导入和导出操作必须记录审计日志，导出文件视为敏感数据。
- 明文只在用户当前会话中短暂存在。
- 明文敏感字段不得通过普通 JSON 明文载荷在网络中传输。

## PWA 安全要求

- Service Worker 只缓存应用壳、静态资源、离线页和非敏感资源。
- Service Worker 不得缓存明文密码、恢复码、主密码相关响应或解密后的保险库数据。
- Service Worker 不得缓存记住账号数据；该数据由登录页客户端逻辑管理。
- 敏感 API 必须使用 `Cache-Control: no-store`。
- 如后续支持离线保险库，只能缓存加密密文，并必须要求用户重新验证主密码后解密。
- PWA 必须部署在 HTTPS 下，开发环境可使用 localhost 例外。
- 安装后的独立窗口仍必须执行同样的认证、授权、加密通讯和会话过期策略。

## 数据边界

- 普通用户只能访问自己的个人保险库和密码条目。
- 普通用户不能访问其他用户数据。
- MVP 不存在管理员查看用户数据的能力。

## 输入验证

- 所有输入进行长度、格式、类型校验。
- 备注字段需防 XSS。
- API 参数需防止越权 ID 枚举。

## 重复提交防护

- 创建和更新接口应支持请求去重。
- 前端保存中禁用提交按钮。
- 服务端对重复 Idempotency-Key 返回相同结果。

## 审计日志

必须记录：

- 登录成功和失败。
- 退出登录。
- 创建、编辑、删除条目。
- 查看或复制主要密码。
- 查看或复制副密码。
- 导入密码条目。
- 导出密码条目。
- 修改安全设置。
- 退出其他会话。

## 安全风险

- 已确认：第一版实施端到端加密，服务端无法解密用户密码库。
- 已确认：非对称通讯算法采用 X25519 + AES-GCM。
- 风险：如果用户丢失主密码和恢复材料，服务端无法恢复保险库明文。
- 行业通用默认：需要防 CSRF、XSS、点击劫持、暴力破解、会话固定。
- 后续迭代建议：支持 MFA、WebAuthn、设备信任、异常登录提醒。
