# UI/UX 要求

## 视觉风格

- 风格：安静、专业、安全感强，适合个人长期高频使用。
- 色彩：以中性浅色或深色工作台为基础，使用绿色/蓝色表达安全和可用状态，警告使用琥珀色，危险操作使用红色。
- 密度：移动端优先，信息应便于手机屏幕扫描；列表、搜索、详情和表单紧凑但不能牺牲可触控性。
- 组件库：使用 MUI 作为前端 UI 组件库，通过 MUI Theme 定制颜色、圆角、排版、间距和组件状态。

## 信息架构

- 导航：移动端优先使用底部导航，包含保险库、生成器、日志、设置。
- 主区域：手机端使用单列页面，列表和详情分页面展示。
- 桌面端：在宽屏下可扩展为侧边导航 + 列表详情双栏。
- 全局搜索：搜索当前普通用户的个人密码条目。
- PWA 安装入口：在合适时机提供“安装应用”提示，不打断核心操作。

## 组件清单

- MUI TextField：输入框、密码输入框、搜索框。
- MUI Checkbox：记住账号。
- MUI IconButton：复制、显示/隐藏、编辑、删除、收藏、刷新生成、外链打开。
- MUI Button：主要操作、次要操作、危险操作。
- MUI BottomNavigation：移动端底部导航。
- MUI Drawer：密码生成器、筛选排序、移动端临时面板。
- MUI Dialog：删除确认、导出敏感提示、恢复码确认。
- MUI Snackbar/Alert：复制成功、保存成功、错误提示。
- MUI Card/ListItem：密码条目卡片和列表项。
- 详情页字段级操作必须使用图标按钮：URL 使用外链图标，Username 使用复制图标，密码字段使用显示/隐藏和复制图标。
- 工具入口：导入、导出。
- 副密码列表组件：展示副密码备注、隐藏值、显示按钮、复制按钮。
- 副密码编辑器：添加、删除、排序副密码，编辑副密码备注。
- 筛选菜单。
- 排序菜单。

## 交互规则

- 密码默认隐藏，显示后 30 秒自动隐藏。
- 复制敏感字段后显示短提示，不在页面保留明文。
- 每条副密码必须有独立复制入口，复制入口应靠近对应副密码备注和值，避免误复制。
- 详情页不得使用文字型 `Show` / `Copy` 按钮；视觉上使用图标，辅助技术通过可访问名称识别。
- 导出入口必须在触发前展示敏感数据提示；导入入口应说明支持格式与数据处理方式。

## Tags 后期设计

- MVP 不设计标签创建、标签编辑和标签筛选流程。
- 设计稿中的标签 chip 若保留，只作为未来功能占位，不作为 MVP 必需交互。
- 后期再补标签选择器、标签管理、标签筛选和批量标签操作。
- 删除使用二次确认。
- 表单保存中禁用重复提交。
- 搜索输入应支持防抖。
- 登录页“记住账号”默认不勾选；勾选后下次打开自动填充账号字段；取消勾选后清除本地保存的账号。

## 响应式要求

- 手机端为主设计目标：360px-430px 宽度必须完整可用。
- 手机端：底部导航，顶部搜索，单列列表，详情独立页面，新建/编辑使用全屏表单，生成器和筛选使用底部抽屉。
- 平板端：可使用双栏或折叠导航，但不得改变核心操作路径。
- 桌面端：作为响应式增强，可使用侧边导航 + 列表详情双栏。
- 主要操作按钮应位于拇指易触达区域，触控目标建议不小于 44px。

## 状态要求

- 空状态：引导新建第一个条目。
- 加载状态：骨架屏或局部加载指示。
- 错误状态：明确错误原因和可执行恢复动作。
- 无权限状态：说明无法访问并提供返回入口。
- 离线状态：明确说明当前无法同步或读取服务器数据，提供重试操作。
- 已安装状态：PWA 独立窗口下隐藏浏览器相关提示，保留完整导航。

## 可访问性

- 所有图标按钮必须有可访问名称。
- 键盘可操作：Tab 顺序合理，Enter/Space 可触发按钮。
- 文本与背景对比度满足 WCAG AA。
- 表单错误与字段关联。

## Figma 生成要求

- 先生成移动端关键页面，再生成桌面端响应式扩展。
- 包含登录页、密码列表页、条目详情页、新建条目弹层、安全设置页。
- 包含 PWA 安装提示和离线页状态。
- 组件需包含默认、悬停、禁用、错误、加载状态。
- Figma 与实现应尽量映射到 MUI 组件，避免自造复杂控件。
