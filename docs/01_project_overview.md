# PasswdMan2 项目总览

## 项目背景

PasswdMan2 是一个面向普通用户的个人密码管理 PWA 站点，用于安全保存、检索、生成和管理账号密码、密钥、备注等敏感信息。

- 用户明确提出：需要生成密码管理站点需求。
- 用户明确提出：MVP 只实现普通用户功能，不考虑团队与管理员。
- 用户明确提出：客户端与服务端通讯要用非对称加密方式通讯。
- 用户明确提出：项目以 PWA 形式开发。
- 用户明确提出：项目 UI 以移动端为主进行设计。
- 行业通用默认：密码原文不应以明文形式存储，站点应具备主密码、加密存储、会话保护和审计能力。

## 项目目标

- 提供安全的账号注册、登录和退出。
- 登录页支持“记住账号”，避免用户每次重复输入邮箱或账号名。
- 支持普通用户创建和管理个人保险库。
- 支持密码条目的增删改查。
- 每条密码记录支持一个主要密码，以及若干副密码；每个副密码都必须支持独立备注。
- 支持按标题、网址、用户名搜索密码条目。
- 提供导入/导出入口，便于后续从 CSV 或其他密码管理器迁移数据；MVP 至少在界面中预留入口和安全提示。
- 提供强密码生成器。
- 提供基础审计日志，记录关键安全操作。
- 提供个人安全设置，如修改主密码、管理会话、恢复码。
- 客户端与服务端之间的敏感通讯必须使用非对称加密机制保护，至少覆盖注册、登录、主密码相关操作、密码条目创建/更新/查看等接口。
- 第一版采用端到端加密：服务端只同步加密后的密码库和被主密码派生密钥加密的 Vault Key，用户在任意设备输入主密码后，本地派生密钥解开 Vault Key，再用 Vault Key 解密同步来的密码数据。
- 以 PWA 形式交付，支持添加到主屏幕、独立窗口运行、基础离线壳和网络状态提示。
- UI 采用移动端优先设计，优先保证手机竖屏下的登录、检索、查看、复制、新建和编辑体验。

## 目标用户

- 访客：未登录用户，可访问登录、注册、找回入口。
- 普通用户：管理自己的个人账号密码和安全设置。

## 核心价值

- 降低弱密码和重复密码风险。
- 将个人敏感凭据集中加密管理。
- 提高账号检索、复制和更新效率。
- 为关键操作提供可追踪的安全记录。

## MVP 定义

MVP 必须包含：

- 账号注册、登录、退出。
- 记住账号：仅记住登录邮箱或账号名，不记住登录密码、主密码、会话令牌或任何密钥。
- 主密码设置和验证。
- 默认个人保险库。
- 密码条目的增删改查。
- 每条密码记录包含主要密码、副密码列表和副密码备注。
- 条目搜索、收藏、归档。
- 导入/导出入口：保险库页和设置页提供数据导入、数据导出入口；完整格式兼容可后续迭代。
- 密码生成器。
- 基础审计日志。
- 基础安全设置：修改主密码、恢复码、活跃会话查看或退出。
- 非对称加密通讯机制：服务端公钥获取、客户端加密请求、服务端解密处理、响应保护或会话密钥协商。
- PWA 基础能力：Web App Manifest、Service Worker、安装提示、应用图标、离线壳、静态资源缓存、网络异常提示。
- 移动端优先 UI：底部导航、单列页面、全屏表单、底部抽屉、适合拇指操作的主要按钮。

## 非目标

- 不在 MVP 中实现团队、组织、成员邀请或共享权限。
- 不在 MVP 中实现团队管理员或系统管理员后台。
- 不在 MVP 中实现浏览器插件。
- 不在 MVP 中实现原生移动 App；移动端通过 PWA 响应式体验覆盖。
- 不在 MVP 中实现企业级 SSO。
- 不在 MVP 中实现自动填充网页表单。
- 不在 MVP 中实现完整第三方密码管理器格式兼容；MVP 只要求预留导入/导出入口和基础 CSV 方向说明。
- 不在 MVP 中实现标签创建、标签编辑、标签筛选或标签批量管理；tags 作为后期开发项目。

## 已确认技术事项

- 用户明确提出：后端框架采用 Python + FastAPI，部署方式使用 Docker Compose，并使用 Nginx 代理。
- 用户明确提出：数据库采用 PostgreSQL。
- 用户明确提出：ORM/迁移采用 SQLAlchemy + Alembic。
- 用户明确提出：非对称通讯采用 X25519 + AES-GCM。
- 用户明确提出：第一版服务端只同步加密后的密码库和被主密码派生密钥加密的 Vault Key。

## 待确认事项

- 待确认事项：MFA 是否必须进入第一版，还是只预留后续入口。
- 待确认事项：是否需要支持 TOTP 一次性验证码密钥保存。
- 待确认事项：PWA 是否允许离线查看已解锁的加密条目。AI 推理建议：MVP 不缓存完整保险库，不离线展示敏感明文。
- 待确认事项：导入/导出的文件模板和字段映射后续确认。
