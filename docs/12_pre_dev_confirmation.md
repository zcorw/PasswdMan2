# 开发前确认

## 目标

在开始编码前，固化 PasswdMan2 MVP 的产品范围、技术决策、安全边界和暂不实现项，避免开发过程中频繁返工。

## 已确认范围

| 项目 | 结论 | 状态 |
|---|---|---|
| 产品形态 | 个人密码管理 PWA | 已确认 |
| 用户范围 | 只支持普通用户，不做团队和管理员 | 已确认 |
| UI 方向 | 移动端优先，桌面端为响应式扩展 | 已确认 |
| 设计稿 | 以当前 Figma 文件为 MVP 设计基准 | 已确认 |
| 密码记录 | 每条记录包含主要密码、多个副密码、副密码备注 | 已确认 |
| 副密码复制 | 每条副密码需要独立复制入口 | 已确认 |
| URL 操作 | 详情页 URL 只提供新窗口打开入口 | 已确认 |
| Username 操作 | 详情页 Username 只提供复制入口 | 已确认 |
| 记住账号 | 登录页只记住邮箱或账号名，不保存密码和密钥 | 已确认 |
| 导入/导出 | MVP 提供入口和安全提示，完整功能后续实现 | 已确认 |
| Tags | 不进入 MVP，作为后期开发项 | 已确认 |
| 后端框架 | Python + FastAPI | 已确认 |
| UI 组件库 | MUI | 已确认 |
| 数据库 | PostgreSQL | 已确认 |
| ORM/迁移 | SQLAlchemy + Alembic | 已确认 |
| 非对称通讯 | X25519 + AES-GCM | 已确认 |
| 第一版端到端加密 | 服务端只同步加密密码库和被主密码派生密钥加密的 Vault Key | 已确认 |
| 部署方式 | Docker Compose | 已确认 |
| 反向代理 | Nginx | 已确认 |
| 第三方依赖策略 | 遇到成熟第三方仓库或库时优先采用，不自行重复实现 | 已确认 |

## MVP 必须实现

- 普通用户注册、登录、退出。
- 登录页记住账号。
- 主密码初始化。
- 默认个人保险库。
- 密码条目 CRUD。
- 主要密码、副密码、副密码备注。
- 搜索、收藏、归档。
- 密码生成器。
- 审计日志。
- 安全设置：主密码、恢复码、活跃会话。
- PWA：Manifest、Service Worker、安装提示、离线页、静态资源缓存。
- 客户端与服务端敏感通讯使用非对称加密机制。
- 导入/导出入口。

## MVP 不做

- 团队、组织、成员邀请、共享权限。
- 管理员后台。
- 原生移动 App。
- 浏览器插件。
- 企业 SSO。
- 自动填充网页表单。
- 离线完整保险库。
- 完整第三方密码管理器导入导出。
- Tags 创建、编辑、筛选、批量管理。

## 安全边界

- 不保存明文登录密码。
- 不保存明文主密码。
- 服务端不保存主密码派生密钥。
- 服务端不保存 Vault Key 明文。
- 服务端只同步加密后的密码库和被主密码派生密钥加密的 Vault Key。
- 用户在任意设备输入主密码后，本地派生密钥解开 Vault Key，再用 Vault Key 解密同步来的密码数据。
- 不保存明文主要密码、副密码、副密码备注。
- 不在日志中记录任何敏感明文。
- 不在 Service Worker Cache 中缓存敏感 API 响应。
- 导出文件视为敏感数据。
- 记住账号只保存邮箱或账号名。
- 详情页显示或复制主要密码、副密码都必须记录审计日志。

## 开发原则

- 如果开发中遇到已有成熟、活跃维护、许可证兼容且安全记录良好的第三方仓库或库，应优先直接使用，不自行重复实现。
- 安全关键能力优先采用被广泛验证的第三方库，包括密码哈希、X25519、AES-GCM、安全随机数、输入校验、测试和 PWA 工具。
- 引入第三方依赖前需要检查维护状态、许可证、依赖体积、安全风险、浏览器兼容性和与 FastAPI、React、MUI、Docker Compose 技术栈的兼容性。
- 引入后需要在 README 或对应开发文档中记录依赖用途、版本范围、替代方案和安全注意事项。

## 开发顺序建议

1. 项目骨架、PWA 基础、环境配置。
2. 认证、会话、记住账号。
3. 非对称加密通讯基础模块。
4. 数据模型和数据库迁移。
5. 个人保险库与密码条目 CRUD。
6. 主密码、副密码、副密码备注 UI 与 API。
7. 密码生成器。
8. 审计日志。
9. 安全设置。
10. 导入/导出入口。
11. 移动端视口验收和 PWA 验收。

## 开发启动前需要用户确认

- 是否接受推荐前端框架 React + TypeScript + Vite。
- 是否确认 MVP 不实现完整离线保险库。
- 导入/导出的文件模板和字段映射后续确认。

## 部署拓扑

- `frontend`：PWA 前端构建与静态资源。
- `backend`：Python + FastAPI API 服务。
- `postgres`：PostgreSQL 数据库。
- `nginx`：反向代理，负责 HTTPS 终止、静态资源、PWA 文件响应和 API 转发。
